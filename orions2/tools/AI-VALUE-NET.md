# 小神经网络价值函数：A 方案实测报告

结论先行：**没有达到 55% 的启用水准，因此没有接入游戏**。四组 A/B 的胜率都在 45%–49% 之间，
95% 置信区间整体落在 50% 以下或刚好覆盖 50%，也就是说「1-ply 搜索 + evalState」这套手工评估
并不怕这个小网络，硬塞进去反而会掉胜率。

不过这一轮顺带挖出了两个真实 bug，其中一个让 **AI 的模拟搜索从来没有真正跑起来过**。
修好之后，AI 对旧版 AI 的胜率是 **75.1%**。

---

## 1. 做了什么

| 组件 | 文件 | 作用 |
| --- | --- | --- |
| 状态特征 | `js/value-net.js` | 63 维、以「当前行动方」为视角的对称特征；浏览器与 Node 共用 |
| 自对弈采样 | `tools/selfplay.js` | 双方都用现有启发式 AI，加 10% 探索；每个决策点记录状态，终局回填胜负标签 |
| 训练 | `tools/train-value-net.js` | 纯 JS 的 63-40-20-1 MLP，tanh + sigmoid，Adam + 早停 |
| 推理 | `js/value-net.js` | 空值安全；未加载权重时 `predict()` 返回 `null`，AI 行为完全不变 |
| A/B | `tools/ab-value-net.js` | 同一副牌、交替先后手，只让 B 方使用网络；输出胜率、Wilson 95% CI、z/p |

融合方式有两种，都实测过：

- `minmax`：把 `evalState` 和网络概率各自在候选集内归一化到 [0,1]，再按权重线性混合；
- `rank`：改用名次而非数值融合，避免网络的小幅噪声被归一化放大；
- `tiebreak`：只在启发式评分几乎打平（差距 < 8%）的候选中用网络排序，属于最保守的用法。

## 2. 数据与模型

- 自对弈 **3000 局**（修复后的引擎），22.5 回合/局，共 **132,722 条状态**（含镜像增广）。
- 训练/验证 9:1，验证集 13,273 条。
- 验证集：loss 0.493，**AUC 0.831**，准确率 73.8%，Brier 0.167。
- 训练集：AUC 0.854，准确率 75.7%（过拟合不严重，早停在第 21 轮）。

单看这些指标，网络是「学到了东西」的：给定一个局面，它判断最终胜负的排序能力明显好于随机。
问题出在它被要求做的事情上——不是判断「这个局面好不好」，而是判断「这两个只差一张牌的兄弟局面
哪个更好」。后者需要的分辨率高得多，而绝对胜率模型给不出来。

## 3. A/B 结果

每组 2000 局，同一副牌、先后手交替、同一随机种子，唯一变量是 B 方是否使用网络。

| 配置 | B 方胜率 | 95% CI | p | 判定 |
| --- | --- | --- | --- | --- |
| 权重 0.5 · rank 融合 | **45.4%** | 43.2–47.6% | <0.001 | 明显更差 |
| 权重 0.5 · minmax 融合 | **47.0%** | 44.8–49.2% | 0.007 | 更差 |
| 权重 0.3 · rank 融合 | **48.6%** | 46.4–50.8% | 0.21 | 无差异 |
| 权重 1.0 · 仅同分时裁决 | **48.9%** | 46.8–51.1% | 0.35 | 无差异 |

对照实验（两边都不开网络）4000 局为 51.1%（CI 49.6–52.7%），说明测试台本身没有系统性偏向，
上述差异不是座位或牌序造成的。

> 说明：本轮数据采集于 AI 加入「回合开始先判斩杀」之前；该改动只影响对战强度，不影响
> 网络本身的训练与评估结论。

**按约定（>55% 才内置）不启用。** 代码保留在仓库里，`index.html` 不加载 `value-net.js`，
所以正式游戏的行为、体积和启动速度都不受影响；这些文件只是离线实验工具。

## 4. 为什么会输给手工评估

1. **评估目标错位**：网络学的是「这个局面我最终赢的概率」，而搜索需要的是「A 局面比 B 局面好多少」。
   两个兄弟局面的绝对胜率可能只差 0.01，而网络的误差远大于这个差。
2. **手工评估已经很贴合这个游戏**：`evalState` 里的「血量差 + 场面价值差 + 直击潜力差 + 法力差」
   正好是 1-ply 搜索叶节点最需要的量，网络没有额外的信息可补。
3. **标签噪声大**：一局 22 回合，同一局面之后的随机性（牌序、AI 探索）会淹没细微的决策差异。
4. **特征里没有「隐藏信息」**：这游戏没有手牌，牌库是公开的 24 张书页，网络能看到的和评估函数
   看到的几乎是同一批数字。

## 5. 副产品：两个真实 bug（比网络本身重要得多）

### 5.1 `clone()` 丢字段，AI 的模拟搜索从未生效

`Game.clone()` 没有复制 `cardStats`，而 `playCard()` 的第一件事就是 `bumpCard()`。
于是每次「克隆 → 试打一张牌」都会抛 `Cannot read properties of undefined`，被 `simulateOption`
的 `catch` 静默吞掉，返回 `null`。结果是：

- 所有候选的 `simScore` 都是 `null`；
- 排序退化成纯启发式评分；
- 界面上完全看不出来，只是 AI 下得比设计意图弱很多。

修复：`clone()` 补齐 `cardStats`、`castingMana/Element`、`castingCardId`（以及网络/探索开关）。

量化收益（1500 局，同一副牌、交替先后手）：

| 对局 | 胜率 |
| --- | --- |
| 修复后 AI vs 旧版（无模拟）AI | **75.1%**（1124 : 376，CI 72.7–77.1%） |

### 5.2 两处无限递归（会直接卡死页面）

自对弈跑到第 208 号种子时进程 OOM。定位到两类「伤害反弹」死循环：

| 卡牌 | 触发方式 | 修复 |
| --- | --- | --- |
| 刀客 BLADE MASTER ×2 | 受伤 → 对每个敌人各 1 点 → 对方也是刀客 → 反弹回来 → 无限递归 | 溅射伤害不再触发对方的溅射（`bladeSplash` 标记），并加 `chain` 深度上限 |
| 元素法师 ELEMENTALIST ×2 | 魔法链接互相转移伤害 → 来回反弹 | 链接只转移一次（`chain > 0` 不再转发） |

这两张牌在正常对局里同时出现两次并不罕见，之前的版本一旦触发就会让浏览器标签页直接卡死。
另外给 `damageCreature` 加了 `chain > 8` 的硬保护，给自对弈加了单局日志上限，避免以后再出现
同类问题时整批任务被拖死。

## 6. 复现方式

```bash
# 1) 采样（约 95 秒 / 3000 局）
node tools/selfplay.js --games 3000 --seed 5000 --explore 0.1 --mirror 1 \
     --out tools/data/sp3.json

# 2) 训练（约 45 秒）
node tools/train-value-net.js --data tools/data/sp3.json \
     --hidden 40,20 --epochs 30 --lr 0.004

# 3) A/B（约 75 秒 / 2000 局）
node tools/ab-value-net.js --games 2000 --weight 0.5 --blend rank --seed 30001

# 4) 验证 clone 修复的价值（B 方关闭模拟）
node tools/ab-value-net.js --games 1500 --weight 0 --disableSimB 1 --seed 41001
```

> 训练数据文件较大（`sp3.json` 约 36 MB），仓库里只保留了 4000 行的 `tools/data/sample.json`
> 作为格式样例；按上面第 1 步可随时重新生成。

## 7. 如果还要继续

按性价比排序，值得试的是这三条，而不是把现在的网络再调参：

1. **把网络放到更深的位置**：现在是 1-ply（我出一张牌 + 对手快棋一手）。如果做 2-ply 或对每个候选
   做多次 rollout，叶节点的评估误差会被平均掉，网络的长处才用得上；代价是 AI 每回合从 8 ms 涨到
   几十毫秒，需要配时限。
2. **改成「优势网络」**：不学绝对胜率，而是学同一状态下两个动作的偏好（pairwise / Bradley-Terry），
   训练信号直接对准搜索真正需要的比较。
3. **蒸馏而不是增强**：用现有搜索当老师，让网络去拟合 `evalState` 的排序，只用来加速（减少模拟次数），
   不指望它更强。

如果只是想让 AI 更强，**修好 clone 之后已经有 75% 的提升**，继续做搜索深度（对手用完整候选而非快棋）
比换评估器更划算。
